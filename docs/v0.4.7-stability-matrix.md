# v0.4.7 Stability Matrix

This is the execution record for the P0/P1 stability work. It deliberately separates source tests, browser tests, staged artifact tests, and live deployment (which is not part of this checkpoint).

## P0 lifecycle and identity coverage

| Contract | Concrete protection | Focused coverage |
|---|---|---|
| Queued Prompt | Session-scoped FIFO, immutable queue snapshot, dispatch only after settlement | `tests/server/prompt-queue-steering.test.ts`, `tests/prompt-scheduler.test.ts`, `tests/web/queue-dispatch-reconciliation.test.ts`, `e2e/ui.spec.ts` |
| Secondary Prompt | Secondary runtime queue and settlement are independent from Primary | `tests/server/prompt-queue-steering.test.ts`, `tests/server/runtime-recovery-capacity.test.ts`, `tests/web/prompt-consistency.test.ts` |
| Uncertain delivery | Unknown RPC outcome returns `202 deliveryUncertain`, fences the next write, and remains observable until Runtime proof | `tests/server/prompt-queue-steering.test.ts`, `tests/server/runtime-bootstrap-drafts.test.ts`, `tests/prompt-evidence.test.ts`, `tests/web/prompt-consistency.test.ts` |
| Retry-before-HTTP | SSE retry facts are replayed into the Browser PromptOperation before HTTP identity binding | `tests/prompt-coordinator.test.ts`, `tests/web/prompt-retry-projection.test.ts` |
| Abort during retry | Abort settles the Prompt through the terminal process failure path and never invents retry cancellation | `tests/server/state-diagnostics-route.test.ts`, `tests/retry-lifecycle.test.ts`, `tests/web/prompt-retry-projection.test.ts` |
| Session replacement | Old Runtime/process generation cannot paint or settle the replacement Session | `tests/web/app-replacement-generation.test.ts`, `tests/web/app-replacement-maintenance.test.ts`, `tests/fast-mode-status.test.ts` |
| Session deletion | Prompt operation, local Composer state, cache and late async work are retired at deletion | `tests/prompt-coordinator.test.ts`, `tests/composer-state.test.ts`, `tests/web/session-inventory-mutations.test.ts` |
| A → B → A | Navigation epoch and pane revision fence stale work even when the Session ID is revisited | `tests/web/pane-navigation-authority.test.ts`, `tests/web/session-navigation-gate.test.ts`, `tests/web/app-replacement-maintenance.test.ts` |
| Multi-window ordinary writes | Ordinary Prompt submissions from separate browser windows enter one Session FIFO; destructive Rename/Delete remain exclusive-control operations | `tests/server/prompt-queue-steering.test.ts`, `tests/server/window-control-lifecycle.test.ts`, `tests/session-control.test.ts` |

The server-level multi-window regression is intentionally identity-oriented: two window client IDs submit different Prompts to one Session, and the second Prompt must be queued rather than racing Pi. This does not weaken the exclusive-control boundary for destructive mutations.

## P1 CI and release hygiene

- Branch verification is isolated to `main` pushes and pull requests targeting `main`.
- Tag verification is isolated to `v*` tag pushes in `.github/workflows/windows-release-ci.yml`.
- Every third-party GitHub Action is pinned to a full commit SHA and retains a human-readable version comment.
- Tag CI sets `PI_CHAT_RELEASE_MODE=1` and `PI_CHAT_RELEASE_TAG`, so `build-identity.json` cannot silently describe a different revision.
- Release packaging requires a clean worktree, a staging directory distinct from live `dist`, a tag matching `v<packageVersion>`, and a manifest/checksum generated from the same ZIP.
- The tag workflow builds the release candidate from an independent temporary staging tree, runs artifact tests, packages the ZIP, verifies the portable checksum and manifest revision, and uploads the verified candidate as a workflow artifact.
- `SECURITY.md` is included in the Windows package.

## Explicitly out of scope for this checkpoint

- Live Pi Chat restart or `dist` promotion.
- Real provider retry against the live listener.
- A new license choice.
- Windows browser launcher modernization (P2 evaluation).
- A second Runtime, Session, Prompt, retry, Steer, or transcript authority.
